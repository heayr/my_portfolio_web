## ⚡ 1. Performance Engine & 120 FPS Optimization

### 1.1. Зачем `useRef`: Direct DOM Mutation (Zero-React-Reconciliation) & Изоляция мутаций
* **Проблема частоты событий (Event Flooding):** Обработчики мыши (`onMouseMove`) и жестов трекпада на современных экранах (ProMotion 120 Гц, игровые сенсоры) стреляют с частотой до **500–1000 раз в секунду**. 
* **Почему `useState` здесь катастрофичен:** Если сохранять `mouseX` и `mouseY` в React State, каждый микрон движения курсора вызывает вызов функции компонента, создание десятков замыканий, работу Garbage Collector и запуск фазы reconciliation (диффинг Virtual DOM). На 120 FPS это неизбежно приводит к пропуску кадров (jank) и нагреву процессора.
* **Решение в проекте (`CurtainFooter.tsx`, `ContactCardItem.tsx`):**
  - Координаты курсора и подсветки **никогда** не попадают в React State.
  - Используются мутабельные ссылки `useRef<HTMLDivElement>(null)` с прямой модификацией стилей в нативном событии:
    ```ts
    // 1. Курсорный spotlight в футере:
    footerSpotlightRef.current.style.opacity = '1';
    footerSpotlightRef.current.style.background = `radial-gradient(850px circle at ${px}px ${py}px, rgba(245, 158, 11, 0.14), transparent 70%)`;

    // 2. Аппаратное ускорение трансформаций:
    cursorRef.current.style.transform = `translate3d(${clientX}px, ${clientY}px, 0)`;
    ```
  - Использование `translate3d` переносит расчет геометрии целиком на **GPU Compositing Layer** без триггера Layout & Repaint в браузере.
  - **Хранение служебных инстансов:** `useRef` хранит ID анимационных кадров `requestAnimationFrame`, таймеры и ссылки на синглтоны (Lenis scroll), позволяя управлять жизненным циклом без паразитных перерисовок дерева.
  - **Результат:** 0 вызовов React re-render при движении курсора, стабильные 120 FPS.

### 1.2. Зачем `useMemo`, `useCallback` и `React.memo`: Трехуровневый щит от ре-рендеров
* **Проблема ссылочной целостности (Referential Equality):** В JavaScript литералы объектов и функций не равны по ссылке: `(() => {}) !== (() => {})` и `[{ id: 1 }] !== [{ id: 1 }]`. Если родительский компонент (`CurtainFooter`, `Header`, `HeroSection`) рендерится, все немемоизированные функции и массивы создаются заново. В результате все дочерние компоненты (даже обернутые в `React.memo`) сбрасывают оптимизацию и рендерятся вхолостую.
* **Архитектурное решение в проекте:**
  1. **Уровень 1 — Стабильные ссылки на функции (`useCallback` / стабильные хендлеры):**
     - Хендлеры действий (`handleCopyEmail`, `handleScrollToTop`, `toggleLocale`, `toggleTheme`) сохраняют идентичность между рендерами и не провоцируют ре-рендер передаваемых компонентов (`Button`, `ContactCardItem`).
  2. **Уровень 2 — Стабильные массивы и данные (`useMemo`):**
     - Все списки проектов, карточки контактов (`getContactCards`) и манифесты мемоизируются с зависимостью исключительно от `locale`. При смене темы или скролле новые массивы не генерируются.
  3. **Уровень 3 — Блокировка Virtual DOM Diffing (`React.memo`):**
     - Все атомарные и секционные компоненты (`Button`, `Badge`, `GlassCard`, `MoscowClock`, `MorphingToggleIcon`, `SectionHeader`, `ContactCardItem`, `ProjectCard`) обернуты в `React.memo`.
     - Благодаря уровням 1 и 2 React видит, что `prevProps === nextProps` (строгое сравнение по ссылке `Object.is`), и **полностью пропускает рендеринг поддерева**.
  - **Результат:** Время выполнения JavaScript при интерактивном взаимодействии и скролле сведено к **0 мс**.

### 1.3. HTML5 Canvas Frame Scrubber с субкадровой инерцией
* **Решение (`FrameScrubberCanvas.tsx`):**
  - 55 кадров секвенции отрисовываются на `<canvas alpha: false>`.
  - Интерактивный скролл не меняет кадр мгновенно (дискретно), а использует LERP-интерполяцию (линейная интерполяция) в цикле `requestAnimationFrame`:
    ```ts
    currentFloatFrame += (targetFloatFrame - currentFloatFrame) * 0.12;
    ```
  - Межкадровый temporal crossfade: если кадр дробный (например, `24.4`), canvas плавно смешивает кадры 24 и 25, создавая кинематографическую плавность киноленты.
  - Приоритетная загрузка: 1-й и 55-й кадры загружаются первыми для моментального LCP, остальные 53 кадра кэшируются в фоне.

### 1.4. `IntersectionObserver` Lifecycle Guard
* **Решение (`SparkCanvas.tsx`):**
  - Фоновый генератор искр и частиц отслеживается через `IntersectionObserver`.
  - Как только Hero-секция выходит из зоны видимости при скролле вниз, цикл `requestAnimationFrame` немедленно **останавливается**.
  - Исключен расход батареи на мобильных устройствах и 0% фоновой нагрузки на видеокарту.

### 1.5. Lenis Smooth Scroll Tuning
* **Синхронизация физики:** Настроен плавный скролл с параметром `lerp: 0.09` и аппаратной акселерацией `wheelMultiplier: 1.0`.
* Устранены конфликты с нативным CSS `scroll-behavior: smooth`, который ломал интерполяцию тачпада на macOS и мобильных устройствах.
* При открытии навигационного меню Lenis программно останавливается (`lenis.stop()`), блокируя паразитный скролл страницы под оверлеем.

## 💎 3. Универсальные UI-примитивы & True Polymorphism (Design System Core)

В проекте заложен строгий эталон разработки базовых атомарных компонентов (`Button`, `Badge`, `GlassCard`, `SectionHeader`). Каждый UI-примитив обязан отвечать 4 правилам:

### 3.1. Канонический паттерн True Polymorphism (`as` prop)
Компоненты не завязаны на жесткий HTML-тег, а умеют динамически рендериться как любой валидный элемент или сторонний компонент (`as={Link}`, `as="a"`, `as="span"`, `as="section"`):

```tsx
// 1. Базовые кастомные пропсы компонента
export interface BaseButtonProps {
  variant?: ButtonVariant;
  size?: ButtonSize;
  icon?: React.ReactNode;
  iconRight?: React.ReactNode;
  className?: string;
  disabled?: boolean;
  href?: string;
  type?: 'button' | 'submit' | 'reset';
}

// 2. Дженерик-тип с отсечением конфликтов и пропа 'as'
export type ButtonProps<E extends React.ElementType = 'button'> = BaseButtonProps & {
  as?: E;
} & Omit<React.ComponentPropsWithoutRef<E>, keyof BaseButtonProps | 'as'>;
```
* **Зачем `Omit<..., keyof BaseProps | 'as'>`:** Исключает конфликт между нативными пропсами выбранного HTML-тега и нашими кастомными пропсами (например, нативным `size` у `<input>` и нашим `ButtonSize`), а также исключает рекурсивные ошибки TypeScript при выводе `as`.
* **Smart Fallback:** Если проп `as` не передан, но передан `href` — компонент автоматически рендерится как `<a>`, без ошибок компилятора и без необходимости вручную писать `as="a"`.

### 3.2. Встроенная безопасность & Safe Defaults («Защита от дурака»)
Все потенциальные риски безопасности и верстки изолированы и купируются внутри примитива:
1. **Защита ссылок от Tabnabbing:**
   При передаче `target="_blank"` компонент **гарантированно** выставляет `rel="noopener noreferrer"`. Пользовательские пропсы не могут случайно снять эту защиту.
2. **Дефолтный `type="button"` для кнопок:**
   По стандарту HTML тег `<button>` без явного `type` имеет `type="submit"`. Внутри форм это приводит к случайной отправке формы при клике на иконку или переключатель. Примитив `Button` и кликабельный `Badge` принудительно проставляют `safeProps.type = restProps.type || 'button'`.

### 3.3. Сквозной `forwardRef` в полиморфных контейнерах (`GlassCard`)
Карточки и контейнеры поддерживают проброс нативного DOM-рефа через `React.forwardRef` с сохранением полиморфной типизации:
* Внешние движки анимации (Lenis, GSAP, Framer Motion) и функции измерения координат (`getBoundingClientRect` для dynamic spotlight) получают прямой доступ к DOM-ноде.
* Исключены предупреждения React о потере `ref`.

### 3.4. Семантическая типографика и SEO-иерархия (`SectionHeader`)
* Запрещен хардкод заголовков `<h2>`.
* Компонент принимает `asHeading?: 'h1' | 'h2' | 'h3' | 'h4' | 'h5' | 'h6' = 'h2'` и `as?: 'div' | 'header' | 'section' = 'div'`.
* Сохраняет строгую визуальную иерархию (Monospace Tag `//` ➔ Bold Heading ➔ Readable Description), позволяя гибко управлять семантическим деревом документа для 100/100 Lighthouse SEO и A11y.

### 3.5. Single Source of Truth & Zero-Duplication
* **Единые часы (`MoscowClock.tsx`):** Ровно один хук `useMoscowClock` с синглтон-форматтером `Intl.DateTimeFormat` на весь проект. 0 утечек памяти, 0 дублирования интервалов.
* **Единый морфинг-индикатор (`MorphingToggleIcon.tsx`):** Единая микроанимация «2 полоски ↔ симметричный крестик X» для хедера и аккордеона FAQ.
* **Устранение JSX-ветвлений (`ContactCardItem.tsx`):** Замена конструкций `if (type === 'button') return <button>... else return <a>...` на единый полиморфный `Component = card.type === 'button' ? 'button' : 'a'`.
* **Устранение внутренних `key`:** Атрибут `key` удален из корней дочерних компонентов и используется строго на уровне родительского `.map()`.

### 3.6. Post-Mortem & Антипаттерны: Разбор 6 реальных ошибок и правила их недопущения
В процессе проектирования и рефакторинга кодовой базы были вскрыты и устранены 6 критических ошибок. Каждая из них зафиксирована здесь как жесткий архитектурный инвариант:

1. **Ошибка 1: Псевдо-полиморфизм без `Omit` пропа `as` и без `href` в `BaseProps`:**
   * *Как было:* Дженерик `ButtonProps<E = 'button'>` по умолчанию брал тип кнопки. В коде компонента был заложен рантайм-фоллбек на `<a>` при наличии `href`, но компилятор TypeScript падал на `<Button href="...">` (`TS2322: Property 'href' does not exist on type 'button'`), так как `href` не был объявлен в `BaseButtonProps`. Кроме того, проп `'as'` не был явно исключен из `ComponentPropsWithoutRef<E>`, что приводило к рекурсивным ошибкам типов.
   * *Инвариант:* `BaseProps` обязан объявлять все сквозные свойства универсального компонента (`href`, `type`, `disabled`), а `Omit` обязан строго исключать `'as'`: `Omit<React.ComponentPropsWithoutRef<E>, keyof BaseProps | 'as'>`.

2. **Ошибка 2: Инверсия порядка спреда пропсов (Дыра в безопасности):**
   * *Как было:* В JSX свойства спредились в порядке `{...safeProps} {...restProps}`. В JavaScript порядок спреда эквивалентен `Object.assign` — последний ключ побеждает. В результате вызывающий код мог случайно передать `rel=""` и стереть защитные атрибуты `rel="noopener noreferrer"`.
   * *Инвариант:* Безопасные системные атрибуты (`safeProps`) ВСЕГДА применяются **последними**: `{...(restProps as any)} {...safeProps}`. Системную защиту нельзя переопределить извне.

3. **Ошибка 3: Мертвые импорты и потеря `forwardRef`:**
   * *Как было:* В `GlassCard.tsx` был импортирован `forwardRef`, но сам компонент оставался обычной стрелочной функцией. Любая передача `ref` в `<GlassCard ref={...}>` (для скролл-анимаций, spotlight-эффектов или GSAP) приводила к предупреждению React и потере доступа к DOM-узлу.
   * *Инвариант:* Все базовые контейнеры и карточки дизайн-системы оборачиваются в канонический `React.forwardRef` с сохранением полиморфной сигнатуры типов.

4. **Ошибка 4: Отсутствие дефолтного `type="button"` у кнопок:**
   * *Как было:* В HTML спецификации любой тег `<button>` без явного атрибута `type` автоматически трактуется браузером как `type="submit"`. При клике на такую кнопку внутри любой формы (или контейнера с формой) происходила несанкционированная отправка формы с перезагрузкой страницы.
   * *Инвариант:* Полиморфный компонент при `Component === 'button'` принудительно проставляет `safeProps.type = restProps.type || 'button'`.

5. **Ошибка 5: Дублирование JSX через ветвление `if-else` вместо полиморфизма:**
   * *Как было:* В `ContactCardItem.tsx` было написано ветвление `if (card.type === 'button') return <button>... else return <a>...`, где 20 строк CSS-классов и разметки были полностью скопированы дважды.
   * *Инвариант:* Никакого дублирования разметки ради смены тега. Используется полиморфный выбор элемента: `const Component = card.type === 'button' ? 'button' : 'a'; <Component ...>{inner}</Component>`.

6. **Ошибка 6: Антипаттерн `key` внутри возвращаемого JSX компонента:**
   * *Как было:* Внутри `ContactCardItem.tsx` на корневых тегах стоял атрибут `key={card.id}`. Проп `key` не попадает в `props` компонента и предназначен исключительно для алгоритма сверки (Reconciliation) React на уровне итератора `.map()`. Его размещение внутри дочернего компонента создавало иллюзию работы ключа и загрязняло код.
   * *Инвариант:* Атрибут `key` живет ТОЛЬКО снаружи, в месте вызова `.map()` (`<ContactCardItem key={card.id} ... />`).

## 🧩 4. Ключевые архитектурные и UX-находки

### 4.1. Морфинг логотипа из Hero в Header (`MorphingWordmark.tsx`)
* В Hero-секции логотип рендерится как монументальный центрированный титр.
* По мере скролла через `framer-motion` / scroll progress логотип плавно уменьшается, меняет координаты и бесшовно паркуется в зарезервированный центральный слот хедера (`w-[200px] h-[30px]`).

### 4.2. Живой таймзон Москвы (`MOSCOW // GMT+3`)
* Автоматический таймер обновляет точное московское время каждую секунду через `Intl.DateTimeFormat` с временной зоной `Europe/Moscow`.
* Размещен в хедере на десктопе и на самом верху выезжающего меню навигации с пульсирующим зеленым индикатором готовности к сотрудничеству (`Open to collaboration`).

### 4.3. Блок манифеста принципов (Arpeggio-style Showcase)
* Реализована 5-колоночная архитектура принципов инженерной разработки, полностью синхронизированная с 5 пунктами навигации:
  1. `[01] WORK` — Коммерческие продукты & SaaS
  2. `[02] PHILOSOPHY` — Архитектурные стандарты & чистый код
  3. `[03] METRICS` — 100/100 Core Web Vitals & SLA
  4. `[04] FAQ` — Ответы на технические и проектные вопросы
  5. `[05] CONTACT` — Прямой канал связи

### 4.4. Эффект «Шторного» футера (Curtain Reveal)
* Футер находится в фиксированном слое под основным контентом страницы с `z-index: 0`.
* Основная страница имеет нижний марджин, равный высоте футера. При доскролле до низа страница плавно приподнимается как театральный занавес, открывая интерактивный футер с виджетом времени, кнопками прямого перехода в Telegram и копированием почты в 1 клик.
